What it is

A desktop API client. The same job as Postman or Insomnia — compose a request, send it, read the response, keep the useful ones — with one difference that changes everything downstream: nothing leaves your machine unless you say so.

The whole HTTP surface

Every method, every body type, authentication, redirects, cookies, proxies, client certificates, cancellation mid-flight. Large responses stream to disk instead of eating your memory.

Variables that make sense

{{baseUrl}} resolves across workspace, collection, environment and request, nearest wins. Secrets go in your operating system's credential store — not the database, not an export, not a sync payload.

Bring what you already have

Imports OpenAPI 3, Postman collections and environments, and cURL commands. Exports to portable JSON, or copies any request back out as cURL.

Scripts and tests

JavaScript before a request and after a response, in a sandbox with no filesystem, network or process access. Write assertions; results appear beside the response.

OAuth 2.0 that works

Authorization code with PKCE through a loopback listener, client credentials, password grant. Tokens are held in memory and attached at send time — never written to the database, an export or a sync.

It opens quickly

Because it is a native window, not a packaged web browser. That is a consequence of how it is built rather than the reason to use it.

Measured, not claimed

Both applications sitting idle on the same machine, measured with scripts/measure-memory.sh in the repository. PSS — the honest number, which divides shared memory rather than counting it twice.

Sync, if you ask for it

Relay works completely without a server, for ever, with no reduced feature set. Turn sync on and you choose where it points.

Run it yourself

One small Rust binary, or a Docker image. SQLite for a single team, PostgreSQL if you prefer. No licence check, no phone-home, no account with us — self-hosting costs nothing and depends on nobody. 

docker run -p 8787:8787 \
  -e RELAY_DATABASE_URL=sqlite:///data/relay.db \
  relay-server

What syncing gives you

  • The same collections on every machine you work from
  • Teammates, with viewer, editor and admin roles
  • Invitations bound to the address they were sent to
  • Live updates over a websocket
  • Conflicts shown side by side — never silently resolved

A conflict is a question, not an accident. Relay shows you both versions and lets you pick; it never quietly overwrites work.

An assistant that cannot read your secrets

Ask it to find a request, write a test, point a collection at staging — anything you could do yourself. It uses your own API key, talks straight from your machine to the provider you pick, and keeps its conversations in the same local database as everything else.

Your key, your provider

Claude, OpenAI, or anything speaking the same shape — Ollama and LM Studio included, so the whole thing can run on your own machine. Relay ships no key and runs no server for this.

It asks before it acts

Sending a request and deleting something always need your say-so, inline, before they happen. A request the assistant sends is indistinguishable at the far end from one you sent — so you get asked.

Secrets stay invisible to it

It can see that a variable called apiSecret exists. It cannot see the value, and credential-shaped headers come back redacted. An agent can be steered by whatever it just read on a web page; it is not a safe place for a password.

Your own tools, too

Point it at an MCP server you run and its tools appear beside Relay's own. Anything someone else's tool offers is always confirmed before it runs.

Getting an account

You do not need one. If you only work on one machine, skip this entirely — Relay is whole without it. An account exists so a workspace can follow you between machines and be shared with people you work with.

Use the server we run

  1. Create an account — an address and a password, nothing else.
  2. Install Relay and open Sync.
  3. Give it this address: https://relay-sync-ct0w.onrender.com

It idles when nobody is using it, so the first request after a quiet spell takes a moment to wake. Your edits queue meanwhile and nothing is lost.

Or run your own

The same server, on your hardware, with no account here at all. One binary or one container, SQLite or PostgreSQL, and nothing phones home. This is the path that was built first, and the one the whole design assumes.

Self-hosting is not a lesser option with features held back. It is the same software, and the hosted one above is simply an instance of it.

How to host it

Get Relay

Built from source today, which takes one command and a few minutes. Signed installers for each platform are on the way.

Build it

git clone https://github.com/l-robinsonl/relay
cd relay
npm install
npm run tauri build

Needs Rust and Node. The binary lands in target/release, and the Linux build also produces .deb, .rpm and .AppImage packages.

A note for macOS

Builds are not code-signed yet, so Gatekeeper will refuse one you did not compile yourself. Right-click the application and choose Open the first time, or clear the quarantine flag: 

xattr -dr com.apple.quarantine /Applications/Relay.app

Windows may show an unknown-publisher warning for the same reason. Linux is unaffected.
