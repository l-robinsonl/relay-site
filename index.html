What it is

Relay does the same job as Postman or Insomnia: write a request, send it, read the response, keep the ones you'll want again. The difference is that nothing leaves your machine unless you ask it to.

The whole HTTP surface

Every method and every body type, plus authentication, redirects, cookies, proxies and client certificates. You can cancel a request while it's still running. Big responses go to disk rather than filling up your memory.

Not only HTTP

GraphQL, with a button that fetches the schema from the endpoint. gRPC, which asks the server what methods it has and fills in the message for you. Websockets and server-sent events, chosen from the same dropdown as GET and POST. A connection keeps the URL, headers, variables and login details you already set up, and opens a live transcript you can type into.

Variables that make sense

Write {{baseUrl}} and Relay fills it in, checking the request first, then the environment, then the collection, then the workspace. Passwords and tokens go in your operating system's keychain, so they never reach the database, an export or a sync.

Bring what you already have

Import OpenAPI 3 files, Postman collections and environments, or just paste in a cURL command. Export to plain JSON, or copy any request back out as cURL.

Scripts and tests

Run JavaScript before a request and after a response. The sandbox can't reach your files, your network or anything else on the machine. Write assertions and the results appear next to the response.

OAuth 2.0 that works

Authorization code with PKCE, client credentials and password grant. Tokens are kept in memory and added as the request goes out, so they're never written to the database, an export or a sync.

Everything you sent, kept

Every request you send is kept with its response, so the one that worked an hour ago is still there to read or run again. Ctrl‑K opens a search box that finds any request, collection or environment without reaching for the mouse.

It opens quickly

Relay is a native window rather than a packaged web browser, so it starts fast and stays small. That's a side effect of how it's built, not the reason to switch.

Measured, not claimed

Both apps sitting idle on the same machine. We used scripts/measure-memory.sh, which is in the repository, so you can run it yourself. The figure is PSS, which shares out memory used by more than one program instead of charging the full amount to each of them.

Share it with your team

On your own you need no server at all, and Relay is complete without one. As soon as a second person needs the same collections, you get a choice most API clients don't offer: run the server yourself, or let us run it. It's the same software either way.

What a team gets

  • The same collections on every machine, for everyone
  • Viewer, editor and admin roles, set from inside the app
  • Invitations that only work for the address they were sent to
  • Changes appear as they happen, with no refresh button
  • Clashes shown side by side, never settled behind your back
  • Secrets stay out of it, because they never leave your keychain

If two people change the same request, Relay shows you both versions and asks which one you want. It never quietly overwrites anybody's work.

Run the server yourself

One small binary, or a Docker image. SQLite if it's a single team, PostgreSQL if you'd rather. No licence check, no seat count, nothing phoning home and no account with us. Self-hosting is free for any number of people. 

docker run -p 8787:8787 \
  -e RELAY_DATABASE_URL=sqlite:///data/relay.db \
  relay-server

This is the version that was built first. The hosted option below is the same software, running on a computer we look after.

What it does

A failed payment never holds your work hostage

If a payment fails, syncing carries on. So does reading, and so does exporting. The only thing that stops is adding another person, and nobody already in the workspace is locked out. An app you keep your API requests in has no business taking them away because a card expired.

And if you'd rather not be billed by anyone at all, the self-hosted server has no seat limit and no billing code in it.

Nothing is held back from the free tier

One person on Relay Cloud gets the whole app and the whole server. Nothing is kept behind the price. We charge for the people you add, and for the AI messages we have to pay for ourselves — not for features.

An assistant that can't read your secrets

Ask it to find a request, write a test, or point a whole collection at staging — anything you could do yourself. Bring your own API key and it talks straight from your machine to whichever provider you choose, or let the Assistant plan cover it and nobody needs a key at all. Either way, the conversations are stored on your disk with everything else.

Your key, your provider

Claude, OpenAI, or anything that speaks the same protocol — Ollama and LM Studio included, so the whole thing can run on your own machine. Using your own key is free and never counted, on every plan including the free ones.

Or no key at all

On Cloud + Assistant the server holds the key, so nobody has to go and get one, pay a second bill, or paste a credential into a settings box. That applies on your own as much as in a team. You get a thousand messages a person a month, and after that your own key takes over, free as always.

That means messages to the AI. The requests you send to your own API are never counted, on any plan. One question can use a few messages if the assistant goes off to look things up, so a thousand works out at a few hundred questions.

It asks before it acts

Sending a request and deleting anything both need your say-so first, right there in the chat. At the far end, a request the assistant sends looks exactly like one you sent yourself — which is why you get asked.

Secrets stay invisible to it

It can see that a variable called apiSecret exists, but not what's in it, and anything that looks like a credential in a header comes back blanked out. An assistant can be talked into things by whatever it just read on a web page, so it's not a safe place to keep a password.

Your own tools, too

Point it at an MCP server you run and its tools show up next to Relay's own. Anything from someone else's tool always asks you first.

The conversations stay with you

They're in the same file as your requests, on your disk, yours to search or delete. An app whose whole argument is that your data is yours can't answer where are my conversations kept with "somebody else's cloud".

Starting a team

Three steps, and the first person pays nothing. Invite the second one when there is a second one.

  1. Create an account — an address and a password, nothing else.
  2. Install Relay and open Sync.
  3. Give it this address: https://relay-sync-ct0w.onrender.com

The server goes to sleep when nobody's using it, so the first request after a quiet spell takes a moment. Your edits wait in line while it wakes up and nothing is lost.

Then invite someone

Go to Sync → Members → Invite and pick a role. They get a link, choose a password, and arrive in the workspace with everything already there. The invitation only works for the address it was sent to, so forwarding the email doesn't let anyone else in.

Adding that second person is the moment a card is needed. Nothing before it asks for one, and there's no trial to run out.

Get Relay

Download it and run it, the way you would anything else. Or build it yourself in one command, if you'd rather not run a binary you didn't compile. Both are properly supported; neither is the lesser option.

Linux .deb .rpm .AppImage macOS .dmg Windows .msi .exe

Or build it

git clone https://github.com/l-robinsonl/relay
cd relay
npm install
npm run tauri build

You'll need Rust and Node. The installers end up in target/release/bundle, with the binary itself in target/release.

First run on macOS and Windows

The downloads aren't code-signed yet, so both will stop you once. On macOS, right-click the app and choose Open the first time, or clear the flag from a terminal: 

xattr -dr com.apple.quarantine /Applications/Relay.app

On Windows, choose More info then Run anyway. Linux isn't affected. What's holding this up is buying certificates, not anything in the code, and building it yourself avoids it completely.
